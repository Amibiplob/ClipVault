# ClipVault 2.0.0 — verification and handoff

## What changed

Existing native Rust/egui architecture, SQLite storage, supported MIME formats, original logo, update-check preference and data directory are retained. v2 adds desktop shortcut adapters; an X11 focus/keyboard-release/paste state machine with manual fallback; stable selection/recency; separate capture/last-used metadata; reboot-aware optional unpinned cleanup; independent layout geometry; divider, themes/font sizing; settings grouping; modal non-destructive editing; installed-executable replacement watching; bounded lazy previews and virtual rows; website and package/repository automation. Legacy original dates that cannot be recovered are not invented.

See CHANGELOG.md, MIGRATION.md and COMPATIBILITY.md for precise behavior. Existing hidden-at-login behavior still waits before initializing the UI, so the rendering framework's first-window mapping does not cause a login flash. Screenshot mode now has an isolated service: it does not monitor the actual clipboard or register desktop shortcuts.

## Remaining blockers and manual acceptance

1. **Real Linux sessions:** Mint Cinnamon first press/repeat/no stray v; desktop conflict ownership and synchronization; GNOME/MATE/Xfce/Plasma; text/image/rich/file paste in named applications; focus/modifier timing; native geometry/maximize/monitor changes; larger-font physical usability; login and actual reboot; real installed upgrade/uninstall; package replacement and no duplicate instances. Use COMPATIBILITY.md and a disposable desktop with non-sensitive test history. No Wayland compositor was available. Most desktop rows remain Untested; Mint is Limited.
2. **Paste capability:** X11 issues a verified-focus XTEST input request, not verified app consumption. Wayland uses “Copied—press Ctrl+V to paste.” A local notify-send feedback attempt is optional; notification delivery is not verified. Unsupported Wayland data-control correctly prevents capture/restoration and explains the limitation.
3. **Browser testing:** the Craft browser walkthrough was refused: `MCP tool call requires approval, but approval policy is never`. Static checks pass, but mobile/desktop browser screenshots, visual overflow, keyboard FAQ/navigation and deployed download destinations remain unverified. The remote repository fetch also failed (cache miss). The website preserves Releases fallback and never assumes v2 assets or a live APT endpoint.
4. **RPM and repositories:** install rpmbuild on a build host and run `scripts/package-rpm.sh`, then exercise RPM installation. Signing keys, protected Actions secrets, hosting credentials and approved release artifacts are unavailable. APT-REPOSITORY.md gives exact signing/publication/clean-system verification steps. No PPA or signed APT repository is live from this task; no website APT command is advertised.
5. **Publication:** enable/verify GitHub Pages using the prepared workflow; run package CI and maintainer desktop acceptance; approve/upload releases and repository artifacts separately. No upload, publish, deploy, system installation, Git commit/tag/push or real-user-history modification was performed. Changes remain local and uncommitted.

For an installed 1.2.0-or-earlier running process, quit it once before launching 2.0.0. The old binary cannot acquire v2's update watcher retroactively. Source implements future newer-file detection, a stable version probe, deferred restart for edits/activation and storage flush; end-to-end replacement/restart acceptance remains unverified.
