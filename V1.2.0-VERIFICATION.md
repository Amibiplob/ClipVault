# ClipVault v1.2.0 verification — 2026-11-10

Current app version: **1.2.0**. Debian revision: **1.2.0-1**. Tests use isolated temporary histories, never the user's database. Earlier verification documents describe earlier builds only.

## Implementation

- Appearance persists `system_title_bar` and `app_font` as additive SQLite JSON settings. Native mode requests desktop decorations and hides custom window buttons. Custom mode supplies Minimize, Maximize/Restore, Close-to-hide, app-name dragging, and eight edge/corner resize regions. Both modes retain resizable geometry.
- Fontconfig enumerates installed scalable outline families. System default uses the desktop sans-serif match, with the bundled interface font as fallback. Selected families persist by name. Missing/unreadable/unsupported fonts fall back; font bytes are validated before egui receives them. The sample updates with the app font. Installed user fonts are never added to packages.
- Both modes share clean 52-point rows, subtle borders and a soft accent selection. Compact has a single list and no metadata, preview or extra toolbar. Comfortable has one right-hand preview at all supported widths, renders full text only once or original image pixels, and has Copy text/Copy image/Copy, Pin/Unpin, editable-text Edit, and Delete actions.
- A non-floating scrollbar always reserves its own lane. Row text and the pin/menu buttons have separate reserved space. Pins differ by filled accent versus muted outline shape.
- General adds Start hidden under Start on login, and Confirm before deleting (default on). The autostart entry uses `--autostart`; manual invocation sends show to an existing instance. Duplicate login starts leave the running window alone. Hidden login monitoring starts before any UI/GL/native viewport exists, avoiding eframe 0.31's unconditional first-window mapping. Shortcut or manual IPC requests then create and focus the window.
- All single-delete paths use the same “Delete this clip?” Cancel/Delete dialog or delete immediately when the setting is off. Clear unpinned history and destructive cleanup-setting changes keep independent confirmations. Automatic cleanup protects pins.
- The bundled offline v1.2.0 changelog waits until the first visible opening. Done or Escape records `changelog_dismissed_version`; About → View changelog reopens it. Screenshot mode suppresses the upgrade modal to capture the actual requested page.
- Cargo, About, AppStream, README, packaging filenames and release notes use 1.2.0. Both package formats include changelog and verification documentation.

## Desktop limits and unverified behavior

The sandbox shell cannot connect to `$DISPLAY` (`xwininfo` reports unable to open display). Real login/logout, physical no-flash observation, native title-bar rendering, moving/maximizing/resizing under X11/GNOME/KDE/Wayland, external application text/image pasting, and installed-package upgrade/reboot persistence remain unverified. Automated command dispatch and MIME-byte tests do not prove those desktop behaviors. Two existing ignored tests require a real X11 clipboard and loopback sockets respectively; they are not counted as passing tests.

The compositor controls native decorations, focus, placement and resize requests. Some Wayland desktops choose their own decoration style. Wayland clipboard monitoring still requires compatible data-control protocols and a desktop binding for `clipvault --toggle`. Fontconfig commands are optional; unavailable Fontconfig leaves a working bundled System default fallback.

No system installation, production mutation, release upload, Git commit/tag/push or publication is part of this work. Package smoke tests extract into temporary directories and do not install packages.
