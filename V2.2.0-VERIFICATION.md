# ClipVault 2.2.0 verification — 2026-11-13

## Implemented

History toolbar reserves the right-hand action and scrollbar lane, wraps the count in its
remaining space and centers both vertically. Clear unpinned keeps the existing confirmation
preference and deletes all unpinned history, including filtered-out rows; its scope explanation
is now in the tooltip and confirmation. Pins, shortcuts, paste activation and stored records
are retained. New image dimensions use an optional serde field compatible with old records;
legacy PNG/JPEG dimensions are read from headers when a visible thumbnail is loaded.

Image rows use a 112×74 aspect-preserving preview in a 94-point row. Text rows use 56 points.
Only visible rows are loaded; the virtual list uses per-row offsets. The LRU holds at most 16
thumbnail textures (480×240 maximum, at most about 7.4 MB RGBA), plus the existing single
bounded detail preview. Decode limits and explicit No preview placeholders handle failures.
Back icon/label share a measured center. About link buttons wrap at their content widths.

The integrated worker detects running package ownership or AppImage runtime, requires a
matching CPU and compatible signed distribution release, verifies Ed25519 metadata before
trusting SHA-256, verifies package identity/version/architecture and uses system authorization
for APT/DNF. AppImages use staged atomic replacement with rollback and a verified Save copy
fallback. Restarts defer edits, pending changes and active update work, flush storage, retain
launch arguments and only report completion in the expected new running version. Existing
external-package replacement detection shares this restart guard.

## External gates and unverified environments

`packaging/update-keys.json` intentionally contains no trusted maintainer key. No private
release key was supplied, no production signature was created, no update was downloaded from
an actual published signed release, and nothing was uploaded or published. Automatic install
is disabled until a maintainer embeds a trusted public key, rebuilds, tests and publishes the
signed metadata and matching packages. See `packaging/UPDATER.md` for exact signing commands,
GitHub Actions secret setup, key rotation, HTTPS redirect policy and manual recovery.

Privileged APT/DNF installation and upgrade transactions, real Polkit cancellation, actual
package locks/dependency failures, real full disks, native Save As dialogs, read-only mounted
AppImage filesystems, FUSE launch, end-to-end app replacement/restart across a real desktop,
physical keyboard/paste and Wayland integration were **not tested** here. Unit error handling,
private temporary file replacement and receipt checks do not establish those results.

Current package targets are Mint 22.x/Ubuntu 24.04 and Fedora 44 x86-64; other RPM releases,
non-x86-64 packages and older glibc systems require their own builds and disposable integration
checks. Repository-managed installations are conservatively directed to the system updater;
manual download is the fallback when ownership, compatibility, trust or write access is unclear.

Existing unrelated source/PPA work was preserved. No commit, push, deployment, provider change,
real user clipboard mutation or user data migration/reset was performed by this update work.
